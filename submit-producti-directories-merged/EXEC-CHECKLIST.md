# 外链自动提交合并版 · 投递执行必过检查单（EXEC-CHECKLIST）

> 用法：**每站执行前与提交/判定后各过一遍**，并把「checklist PASS/FAIL（未过项写明原因）」写入该站记录（§20 交付可见）。
> 原则：**读了不算应用，过了检查单并留痕才算**。新教训必须增量固化为检查项（细则在 SKILL-LOCAL-IMPROVEMENTS.md），不得只进长文档。

## A. 预检 / 识别（开站必过）
- [ ] 1. 可达性：curl/打开首页确认可达；不可达 → unavailable，不耗浏览器。
- [ ] 2. 曝光识别：先用常规手段（导航/页脚/仪表盘/站内搜索及 DOM 链接、按钮、`href`、ARIA/标题属性）按 §19.1 逐项找可执行入口（business 通道→档案→listing→project→免费广告→新闻稿→账号主页→官方 Contact 邮件），并识别内容编辑器（短贴 Note/status 或长文 Post；只记录为 no-action，不执行）。Contact 邮件只接受目标站官方页面公开的邮箱/`mailto:`，按 §19.2 执行。**仅当常规手段未找到任何可验证入口时**，才做首、中、尾视觉识别；常规已发现入口则记录 `Visual fallback: not required — regular entry found`，不得额外视觉扫描。若只有内容编辑器，记 `ineligible`；无任何入口且已完成所需的视觉兜底时，才 `unavailable`。
- [ ] 3. 付费/合作路径不得停：见 Partner/Sponsored/Paid 只标记"付费跳过"，**继续回首页找常规入口**；完成「首页可见入口 + 重定向核验」（§7.8）。
- [ ] 4. 站内去重：优先用站点真实搜索控件完成品牌、变体、规范 URL 与裸域名查询，并检查后台/近期/分类/可及列表；候选必须打开核验归一化出站 URL。命中或用户确认已收录 → `duplicate — no action`。若原生去重能力不存在，记录 `Duplicate check: not available — user-authorized direct attempt`；若能力存在但未能完成（含控件、异步结果、分页、跳转、候选外链核验失败），记录 `Duplicate check: inconclusive — user-authorized direct attempt`。在用户已明确授权直接尝试的批次中，附具体缺口、已完成检查、证据与授权引用后继续一次最终提交；不得因去重未完成中断搁置。提交时 `URL already exists` 或等价回执即为重复结论并停止；不得重试。
- [ ] 5. 登录与营销默认授权：business 通道优先（§18.3）→ Google 直接登录 → Google 账号登录/注册/找回 → 企业邮箱（§18.2）；无费用营销订阅按 §18.4 默认选择，付费/自动续费一律不选。
- [ ] 6. 指纹浏览器：**只读识别**（profile/CDP 端口/业务标签页），**禁碰服务器总控客户端**（§6.1）；**唯一例外：浏览器崩溃时可在客户端执行"重新打开浏览器/重启该 profile"**（恢复执行环境，其余不改）。
- [ ] 6a. 内容面分类（仅内容编辑器）：按 §15 记录 `Content surface` 与证据。短贴、长文和无法分类的编辑器分别记为 `short note — no action`、`long post — no action`、`unknown — no action`；均不得输入或预填内容、保存草稿、交人工完成、提交或发布。界面称为 `Post` 不构成例外；只有内容编辑器的站点记 `ineligible`。非内容编辑器入口记 `not applicable`。
- [ ] 6b. 官方 Contact 邮件预检（仅邮件投递）：当前批次明确授权且 Gmail 发件别名已核验；收件人来自官方 Contact/投稿/资源推荐入口；用 Gmail Sent、Drafts、All Mail 和当前记录完成品牌、规范 URL、目标域名、联系路由去重。已有邮件/草稿/会话 → `duplicate — no action`；不得用第三方、`no-reply`、隐私/法务地址，且不得 CC/BCC、群发或自动跟进。

## B. 填表 / 邮件撰写（仅非内容编辑器最终动作前必过）
- [ ] 7. 流程预识别：先辨识步骤/向导/必填字段/免费档/媒体上传要求；字段卡一次给全。
- [ ] 8. 内容填全：图片（缓存复用）+ 描述 + Profile Details/网站信息全部填全（§16/§16.1）。
- [ ] 9. 受控表单：填后**回读 value** 确认 name/描述稳定写入；提交前必填字段=目标值（§7.9）。
- [ ] 9a. 会重载的方案/链接类型：先选择免费、非互链档位并等页面稳定；任何 `change`/单选操作若导航或刷新，必须在刷新后重新填写并完整回读，未确认不得点最终提交。
- [ ] 10. 媒体上传：异步解锁**等待 done/下一步可用**；过慢/超时 → **保留标签页转人工**（§16.2）。
- [ ] 10a. 验证交接：非内容编辑器表单遇无法自动完成的验证，先完整预填所有可如实填写字段、上传适用素材并选择无费用营销订阅；只可留空未知/不适用字段且须记录原因。保留原标签页、URL、target/tab 与剩余人工动作，禁止关页或留空表（§4/§18.4）。§15 内容编辑器不适用本项。
- [ ] 10b. 邮件撰写回读（仅官方 Contact 邮件）：正文为逐站真实申请，使用规范 URL，说明相关性但不要求 dofollow/互链/排名；不得要求对方发表短贴、长文或客座文章。发送前回读 `From`、`To`、主题、正文、链接和空 CC/BCC；记录受控文案与收件人证据，不在共享记录写明文邮箱。

## C. 提交 / 判定（动作后必过）
- [ ] 11. 首个明确错误即停（fail-fast）："Something went wrong"/页面报错 → 立即停，记 outcome_unknown 带证据，**不重试不续走**（§7.9）。
- [ ] 12. 提交用 `submitAndCapture`；`judgeOutcome` 三信号判定；不确定 → `submission outcome unknown`，**禁止重投**。执行 2–3 轮只读回执核验（当前页面/target、后台、邮箱、公开页），记录轮次与结果；仍无回执则保留页面供人工查验（§7）。
- [ ] 13. 提交后**回查后台**：出现产品草稿/待审记录才算成功路径；后台无记录 → 未成功（§7.9）。
- [ ] 13a. Gmail Send（仅官方 Contact 邮件）：`Send` 是最终动作，只点一次、零次重试。记录 Gmail 原生“已发送”提示及/或匹配 Sent 副本；只可记“邮件已发送，等待回复”，不得写成已送达、已收录、已获外链或已发布。无明确回执时只读检查当前撰写/线程、Sent/All Mail、Drafts/Outbox 2–3 轮，保留页面，绝不重发。

## D. 环境 / 纪律（全程）
- [ ] 14. 开批前清理无关旧标签页；除经授权的官方 Contact 邮件投递外，**不占用 Gmail 等必要标签**；邮件投递只使用已核验发件别名的 Gmail 页面，并保留发送结果不明的页面供人工查验（§6/§7.9/§19.2）。
- [ ] 15. 批内连续执行：**不做阶段性汇报/不中途打断**；全部站点尝试完毕 → 保留阻塞页 → 完成记录审计 → **统一一次性逐站交付**（§8/§20）。仅硬关口（需授权/抉择）与用户主动发问可交互。
- [ ] 16. 状态如实（§0）：点击/跳转/回首页≠成功；只以原生回执/后台/邮箱/公开页为准。**免费档判别（§14.1）：有 Free $0 且可提交 → 按免费路径记 `submitted`/`awaiting approval`（备注条款风险），不得因"反链维护/永久链接维护"等条款误记 `paid-only`**。
- [ ] 17. CDP 脚本重试审议（§6.2）：CDP 失败先记录精确错误与当前 target/页面状态，提出至少两个可区分假设，并完成最小只读判别；仅有新证据且下一次操作实质变化时，才允许一次受控重试。相同脚本/target/参数/等待条件不得重跑；最终 Submit/Publish/Gmail Send 零次重试；记录 `CDP retry decision` 与证据。

---
> 若某一站某条 FAIL：停止该站该动作，记录原因；只有人工/修复后再按同一清单复核通过才可继续或补投。
